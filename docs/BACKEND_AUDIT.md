# Backend audit

Audit performed against the repository state on 2026-11-08. The existing uncommitted deletion of `backend/src/main/java/com/hookforge/delivery/api/MetricsController.java` is user work and was preserved.

## Existing controls observed

- API keys are generated with `SecureRandom`; only a SHA-256 hash and prefix are persisted, and the raw key is returned on creation.
- Authentication is stateless, and form login/basic authentication are disabled.
- Endpoint, delivery, and event lookup code has tenant-scoped repository methods; delivery replay locks the tenant-scoped row.
- Endpoint secrets use AES-GCM with a random 12-byte nonce and 128-bit tag; HMAC signing is implemented in `WebHookRequestSigner`.
- Redirects are disabled, destinations require HTTPS, and response bodies are capped at 8 KiB.
- Delivery insertion is idempotent on `(event_id, endpoint_id)`, and claims use `FOR UPDATE SKIP LOCKED` plus a processing token.
- Event creation writes the event and outbox record in one transaction; Kafka consumption routes idempotently through `ON CONFLICT DO NOTHING` delivery insertion.

## Priority

1. Resolve DNS-rebinding risk by pinning DNS results for the actual socket connection.
2. Shorten outbox database lock duration while retaining at-least-once delivery.
3. Expand integration tests around Kafka recovery, concurrent state transitions, CORS, and tenant isolation.
4. Externalize the encryption key through typed Spring configuration and improve API error consistency.
5. Establish a trusted first-tenant/API-key provisioning workflow; current API requires an existing key.
